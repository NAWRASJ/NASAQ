# Video and audience display

Local video uses the existing GStreamer engine, playlist and business audio controls. There is no independent player that can bypass licensing or prayer holds. MP4, M4V, MOV, MKV, WebM and AVI are accepted as containers; playback still depends on the codecs included in the runtime. MP4 H.264/AAC is the initial verification fixture.

The primary toolbar action is Open media (فتح وسائط), with an audio/video tooltip and accessible name. The Playback menu replaces the old Music heading. The file chooser offers all supported media, video-only and audio-only filters, as well as playlists. These are UI changes to the existing import route, not a second playlist or playback path. Audio-only features such as the microphone, audio CD, announcement recording and optional adhan recording keep their audio terminology.

Display and screens opens a separate resizable floating media window instead of a bottom dock. It can be minimized, maximized, kept on top, or shown full-screen; Escape leaves local full-screen mode. Closing it hides the visual display without stopping playback. Its geometry is stored separately from licensing and business preferences. Local playback starts reveal it, while saving display settings does not. The turntable uses bundled photographic base, record and tonearm layers: detailed forest-green vinyl, ivory label with NASAQ mark, metallic rim, spindle and tonearm. Only the record rotates; the arm rests away from the record while paused. Genuine album artwork appears as a separate sleeve beside the player, with no placeholder when artwork is missing. Track changes clear the sleeve immediately, and stale or fallback covers are rejected. Audio/radio can use a customer-selected image instead. The current player's PCM snapshot drives a 24-band visualizer without consuming the main analyzer's cursor. No artificial audio activity is generated during silence, reconnect, pause or prayer.

A compact lower-right prayer badge shows the countdown including the early-pause setting, or the active prayer hold. With automatic prayer pauses disabled, it shows only the next adhan time and no countdown; without a timetable it disappears. Radio displays a red animated live badge only while playing, amber on reconnect, muted while paused, and no live badge during prayer. Video replaces the turntable. The external audience surface remains an independent, frameless, non-focusable window with a hidden cursor and no playback controls. Windows Extend mode and explicit screen selection are required. It does not select the operator display as a fallback. A missing selected screen hides the audience window and stops playback. Audio output changes while audience display is enabled also stop playback; sound continues to use the application's existing audio output configuration.

Prayer protection uses the existing scheduler and the 0–5 minute early-pause setting. Video is paused with audio, and the audience surface switches to a still image for the entire hold. Images are validated and copied into application-local storage. The default prayer card is available without choosing an image. Restoring the audience window on startup does not start playback.

Decoded frames use a bounded one-frame appsink queue, are polled by the GUI, converted through libgstvideo, and limited to 1920×1080 for display. Video transitions do not crossfade or preload a second video. This first implementation supports local files, not remote video streaming.

## Validation and release boundary

`nasaq_video_tests` exercises real MP4 decoding, seek, early prayer pause, stable paused position and resume, still-image replacement, image ownership, absent-monitor behavior and settings cancellation. A physical external-display test is explicitly skipped when fewer than two screens are present. It must be completed with an extended monitor, including HDMI disconnection and operator minimization, before declaring external-screen hardware verification complete.

Use `scripts/stage-video-runtime.ps1` on the staged runtime to include and verify video plugins and their DLL dependencies. The MSIX manifest registers the video extensions separately from audio. Do not change Windows defaults automatically. Test profiles use temporary settings and in-memory business databases; they must not modify the installed user's license or preferences.

Display settings must also save successfully before any screen or custom image has been chosen. Optional null QString values are persisted as empty text, consistent with the settings table's NOT NULL contract. The five display preferences are committed in a single transaction before applying the new display state. On write failure the transaction is rolled back and the dialog stays open with inline feedback. Regression coverage includes repeated Save, reopening the database, and a simulated write failure after earlier fields have been written.


Local video display titles use the filename (including extension) instead of embedded soundtrack tags. Explicit manual video selection reopens the floating window even if previously closed; automatic resumes still respect hiding. Space toggles play/pause in the main operator window and floating window, excluding editable text, modal dialogs, modifiers and key auto-repeat. The external audience surface remains non-interactive. During video buffering, toggle decisions follow the requested pause state instead of the temporary GStreamer buffering pause.

The local floating video window includes a translucent ivory transport bar with olive line icons, previous/next, play/pause, stop, a seek timeline with elapsed/total time, and full-screen/restore. Pointer activity reveals it for three seconds; active dragging does not hide the bar. Video content suppresses the prayer countdown and spectrum overlays, while music retains both. External audience displays remain free of controls.

The tonearm follows known-duration file progress from the outer groove toward the inner groove, preserves its position on pause/seek, and stays at the middle groove for live radio regardless of stream metadata duration. Prayer/blocked playback parks the arm. Stale queue buffering is cleared only after one second of fresh PCM callbacks and at least 0.8 seconds of advancing playback position while the pipeline is PLAYING; this never starts or unpauses a pipeline.

### Floating controls for songs and live radio
The local floating preview shares its ivory/olive controls across video, audio files and live radio. Files show an absolute seek slider and elapsed/total time; live streams show connection status and never offer seeking, even if metadata supplies a duration. Radio previous/next selects only radio entries in the active playlist and disables unavailable directions. Volume follows the player's current volume without feedback loops.
After three seconds of inactivity, controls fade out over 350 ms. Pointer or keyboard interaction reveals them; dragging a slider and keyboard focus within the panel prevent hiding. Prayer/blocked display hides the panel immediately. External audience displays remain passive.

### Default floating adhan pause card and controls proximity
The floating preview bundles an ivory mosque with olive domes/minaret. Arabic is rendered as real Qt text, exactly «الموسيقى متوقفة حالياً احتراماً للآذان.»; English is rendered separately. The customer's prayer image overrides this default. The default artwork and bilingual resume countdown are confined to the local preview and vanish when prayer hold ends. The countdown derives from the actual prayer_hold_until deadline.
Mouse movement reveals controls only within the panel rectangle plus a 20 px approach margin. Title changes and playback updates no longer reveal the panel. Keyboard interaction remains available. The arm's mounting plate is drawn stationary, with the moving bearing/tube clipped separately around the fixed deck pivot.
